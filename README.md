# 商店跳过（ShopSkip）

在游戏中自动离开已经没有合适购买选项的商店，减少等待时间，不会自动购买商品。

## 功能

- **卡牌商店**：未售商品全部买不起时自动离开；0 星币免费卡牌会保留。
- **售罄与队友转账**：所有卡牌已售罄且已无法转账时自动离开；仍可转账则保留操作机会。
- **ATM**：完成转账后，依据新的商店报价和余额再次判断，不使用转账前可能过期的价格。
- **筹码商店、怪奇糖果机、建筑商店（SDK 前置实验）**：收到服务器购买动作时，如果确实买不起，尝试在购买窗口打开前发送原版取消请求。

## 实验接入与构建

本版本使用**实验性 CesiumLoader SDK `PredictActionPreDispatch`**，**不需要 Harmony / MonoMod**。必须先应用并构建「通用预测动作前置处理」SDK 补丁，再把新构建的 `CesiumLoader.SDK.dll` 放到 ShopSkip 项目的 `refs/` 作为编译引用，确保游戏里运行的加载器也是包含该接口的版本。未打补丁的公开 SDK **不存在**这个接口，直接编译会报类型缺失。

编译后将 `ShopSkip.dll`、`ShopSkip.json` 放入 `AstralParty_ModLoader/mods/ShopSkip/`，完全退出游戏后重新启动。不要再分发或加载之前实验使用的 `0Harmony.dll`。

本版默认订阅 SDK 前置事件；**暂时不执行**筹码、怪奇糖果机、建筑商店的旧窗口内自动取消（但旧服务源码仍保留）。这样在 SDK 事件没有生效时，窗口会照常出现，更容易判断实验结果。卡牌商店和 ATM 的原有自动离开功能不受影响。完成兼容性测试后，可在 `ShopSkipMod.cs` 将 `EnableLegacyWindowFallback` 改为 `true` 恢复旧逻辑；**不要在正式使用时同时启用可能重复处理同一个操作的两套逻辑**。

## 验证方法

1. **观察阶段**：确保前置事件已经订阅；用余额充足或免费商品验证商店正常显示。
2. **余额不足**：测试三个商店的正数报价高于当前星币，检查 `[ShopSkip.PreDispatch]` 日志与窗口是否出现。出现「尝试提前跳过」表示取消请求已被调用，不等于服务端最终接受。
3. **异常与边界**：测试 0 星币报价、未获得完整价格、其他玩家行动、切换场景、断线重连及重复动作。
4. **原版功能**：确认卡牌商店、售罄、队友转账以及 ATM 转账后重新判断正常。

**重要风险**：游戏的 `Request*` 方法会先记录动作已完成，再发送请求；SDK 的通用前置事件也会记录处理序号。不能仅以日志判断已成功关闭窗口，必须观察服务端回执及操作是否卡住。SDK 补丁尚未经过实际游戏测试；请先在单人或受控环境验证。若当前 API 存在兼容性问题，请恢复旧版 ShopSkip 并检查 SDK 的前置处理时序。
