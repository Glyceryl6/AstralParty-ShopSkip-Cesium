# 商店跳过（ShopSkip）

在对局中自动跳过已经没有合适购买选项的商店，减少等待时间，不会帮你自动购买道具。

## 功能说明

- **卡牌商店**：仍有商品但全部买不起时，自动使用原版「离开」按钮。价格为 **0 星币** 的卡牌也算可以买，不会被误跳过。
- **商品已售罄**：卡牌都买完后，如果已无法转账（例如剩余星币不足 5 个，或者转账机会已用），也会自动离开；仍然可以给队友转账时会保留界面。
- **ATM 转账**：完成一次转账后，等待游戏发来更新的卡牌报价和可用星币，再决定是否自动离开；若还有买得起的卡牌，则不会跳过。无需提前保存可能过期的卡牌价格。
- **筹码商店、怪奇糖果机、建筑商店**：正常模式下，确认当前报价买不起时自动使用游戏原版「取消」按钮；单人实验模式下暂停这一自动取消，以便验证真正的提前拦截。

## 使用与兼容性

安装 CesiumLoader 后，将编译好的 `ShopSkip.dll` 和 `ShopSkip.json` 放入 `AstralParty_ModLoader/mods/ShopSkip/`，重启游戏。

本 Mod 不修改服务端价格或游戏协议；仅在价格和状态能够确认时自动操作，信息不完整时保持原样。每约 0.22 秒检查一次，同一窗口不会连续重复取消。

**关于提前跳过：**三个商店的稳定窗口判断现在由独立的 `ShopWindowFallbackService` 处理，卡牌商店和 ATM 仍由 `ShopSkipService` 处理。下面提供一个**默认关闭、仅用于单人实验**的前置拦截入口；它是否能够拦截 HybridCLR 方法，需要在相应运行环境中验证。

## 实验性：单人模式提前跳过（v0.1.3）

默认**关闭**。不影响目前经过界面判断后点击「取消」的稳定功能。本实验尝试在筹码商店、怪奇糖果机和建筑商店打开前拦截各自的购买方法：只有**单人模式、本地玩家、服务端报价明确大于已有星币**时才调用游戏原版取消请求，价格为 0 或信息异常时保留原窗口。

启用实验需要：

1. 在 `AstralParty_ModLoader/mods/ShopSkip/` 创建空文件 `experimental-early-skip.enable`。
2. 将兼容的 `0Harmony.dll` 放到同一目录。**ShopSkip 不再直接引用 HarmonyLib 类型**：只有启用实验并进入单人模式，才会尝试查找已加载的 `0Harmony` 或反射加载本地 DLL。你本地项目中额外添加的编译引用可以保留，但本次源码不需要该引用；本次增量包不会覆盖 `ShopSkip.csproj`。
3. **完全重启游戏后进入单人模式**。日志里首先应出现 `[ShopSkip.WindowFallback] 已暂停三个商店的窗口内自动取消`。此后如果拦截成功，会依次看到 `[ShopSkip.EarlyTest]` 的安装日志、`已进入前置 Prefix`，以及满足条件时的 `单人提前跳过` 日志。
4. 如果只有“已注册补丁”而没有“已进入前置 Prefix”，说明无法确认方法拦截成功；此时商店可能照常打开，且**不会再被旧版窗口自动取消**。如果连安装日志都失败，应检查 `[ShopSkip.EarlyTest]` 的完整异常说明。
5. 删除启用文件、完全重启游戏，即恢复三个商店原有的窗口内自动取消；卡牌商店及 ATM 的自动离开功能始终保留。

**实验期间的工作方式**

| 场景 | 三种非卡牌商店 | 卡牌商店及 ATM |
| --- | --- | --- |
| 实验关闭 | 正常执行窗口内自动取消 | 保持原功能 |
| 实验开启、单人模式 | **暂停窗口内自动取消**，只观察 Harmony 前置拦截 | 保持原功能 |
| 实验开启、非单人模式 | 仍按稳定逻辑处理；不运行前置补丁 | 保持原功能 |
| Harmony 加载/补丁失败（单人实验） | 游戏原生窗口照常打开，方便观察失败，不额外点击取消 | 保持原功能 |

**注意：**通过反射隔离依赖并不意味着 Harmony 能兼容 IL2CPP + HybridCLR；`Assembly.LoadFrom` 和 `Assembly.Load(byte[])` 也可能不受目标运行环境支持。补丁安装成功不代表 Prefix 真正执行。请只在单人测试环境启用，不要在多人真实对局中使用。本项目不使用 P/Invoke、内存地址硬编码或 DLL 字节修改。

计划向 CesiumLoader SDK 贡献的能力：提供由加载器负责、可注销且按模组隔离的“执行前决策”接口，支持明确的 `Continue/SkipOriginal`，并在跳过时由调用方提供合法返回值；必须保留主线程调度、异常隔离、热更新方法兼容性、安装/卸载和多模组冲突测试。
